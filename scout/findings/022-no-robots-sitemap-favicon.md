## No robots.txt, sitemap.xml, or favicon — basic SEO infrastructure missing

**What:** The site has no `robots.txt` (search engines don't know what to crawl), no `sitemap.xml` (search engines can't discover all pages), and no `favicon.ico` (browser tabs show the Vite default icon). These are the three most basic pieces of web infrastructure that every production site needs for search discoverability and professional appearance.

**Where:**
- `frontend/public/` — only contains `bonuses/` and `vite.svg`
- No `robots.txt`, `sitemap.xml`, or `favicon.ico` anywhere in the repo
- Backend serves no SEO-related static files

**Evidence:**

```bash
$ ls frontend/public/
bonuses/  vite.svg

$ grep -ri "robots\|sitemap\|favicon" backend/ frontend/ → no matches
```

The browser tab currently shows the Vite default icon (a purple lightning bolt). MCPLens has a blue gradient logo (`ML`) used throughout the UI but no favicon version of it.

MCPLens has at least 10 public pages that should be indexed:
- `/` (landing)
- `/scan` (scan page)
- `/scan/{domain}` (scan results — thousands of permutations)
- `/pricing` (pricing)
- `/how-it-works` (how it works)
- `/leaderboard` (leaderboard)
- `/report` (ecosystem report)
- `/compare` (compare tool)
- `/terms` (terms)
- `/privacy` (privacy)

None of these are in a sitemap. Google has no structured way to discover them.

**Why this matters:** MCPLens's growth strategy depends on store owners finding it when they search for "Shopify AI agent readiness" or "check my store MCP endpoint." Without basic SEO infrastructure:

1. **No sitemap** — Google can only discover pages by crawling links. The orphaned pages (/report, /compare) may never be indexed. Dynamic scan result pages (`/scan/allbirds.com`) won't be indexed without a sitemap listing them.

2. **No robots.txt** — search engines may crawl and index admin pages, login pages, or API endpoints. A `robots.txt` should block `/last/*` (admin), `/api/*` (API), and allow all public pages.

3. **No favicon** — when a store owner bookmarks mcplens.dev or sees it in their browser tabs, they see the Vite default icon. This signals "unfinished product" and reduces trust. Agencies who bookmark it for client pitches see a purple lightning bolt instead of the MCPLens brand.

These three files take 15 minutes to create and have outsized impact on organic discoverability.

**Suggested Fix:**

1. **favicon.ico** — Export the blue ML logo as a 32x32 favicon and add to `frontend/public/`:
```html
<!-- In index.html -->
<link rel="icon" type="image/svg+xml" href="/favicon.svg" />
```

2. **robots.txt** — Add to `frontend/public/robots.txt`:
```
User-agent: *
Allow: /
Disallow: /last/
Disallow: /api/
Disallow: /dashboard
Disallow: /settings
Disallow: /onboarding

Sitemap: https://mcplens.dev/sitemap.xml
```

3. **sitemap.xml** — Either static in `frontend/public/` or dynamically generated by the Go backend (better, because scan result URLs change):
```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url><loc>https://mcplens.dev/</loc><priority>1.0</priority></url>
  <url><loc>https://mcplens.dev/scan</loc><priority>0.9</priority></url>
  <url><loc>https://mcplens.dev/pricing</loc><priority>0.8</priority></url>
  <url><loc>https://mcplens.dev/how-it-works</loc><priority>0.8</priority></url>
  <url><loc>https://mcplens.dev/leaderboard</loc><priority>0.7</priority></url>
  <url><loc>https://mcplens.dev/report</loc><priority>0.7</priority></url>
  <url><loc>https://mcplens.dev/compare</loc><priority>0.6</priority></url>
  <!-- Dynamic: add /scan/{domain} entries for popular scanned stores -->
</urlset>
```
